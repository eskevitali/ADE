# Каталог моделей и оформление проекта

Страница «Команда агентов» загружает текстовые модели с официального
`https://openrouter.ai/api/v1/models`. Новые модели показаны сверху, есть поиск.
Кэш в памяти backend живёт час; кнопка повторяет загрузку с учётом кэша.
Если OpenRouter недоступен, остаются последний кэш и сохранённые настройки.
Сохранённая модель вне каталога помечается явно. Настройки существующих агентов
и defaults не меняются автоматически. Каталог не проверяет баланс или доступ
конкретного аккаунта. Сам список получается без передачи ключа провайдера.

В форме нового проекта можно выбрать стиль, описать цвета и требования,
загрузить CSS (UTF-8, до 100 КБ), логотип PNG/JPEG/WebP и до восьми шрифтов
WOFF/WOFF2/TTF/OTF. SVG пока не принимается. До 5 МБ на файл, до 20 МБ суммарно;
имена латиницей без путей, повторов и специальных символов.

Материалы сохраняются в `design/`, требования — в `spec/DESIGN.md` и задаче
workflow. Генерация переносит оригиналы в `src/assets/brand/`, включая повторную
генерацию и доработки. Coder получает пути ресурсов и содержимое CSS.
`ade-fonts.css` создаётся автоматически с встроенными данными шрифтов:
это позволяет использовать локальные шрифты в браузерной sandbox без отдельной
авторизации на запрос шрифта. Нужно подключить этот CSS; его имя зарезервировано.
Файлы пользователя не открываются как страницы административного интерфейса.
Внешние CDN и удалённые URL в CSS ограничены существующей политикой sandbox.

Карточка проекта показывает выбранное оформление и список ресурсов. Материалы
входят в хешированный снимок релиза. Результат применения дизайна моделью
не считается визуально проверенным автоматически. Для уже созданного проекта
редактирование комплекта через UI пока не добавлено: загрузка доступна при создании.

Проверено: официальный каталог отвечает; фильтрация текстовых моделей, сохранение
кэша при ошибке, multipart-загрузка, отклонение ошибочных файлов, передача требований
в workflow, сохранность ресурсов при регенерации и в release snapshot.
