# Приведение ADE к Product Vision

## Версия 0.2.0 — проверяемые выпуски (первый этап)

Реализовано:

- Безопасный контракт файлов JSON, поддержка вложенных путей, отказ при traversal,
  дубликатах и неоднозначных именах; полная замена дерева при регенерации.
- Снимки исходников, спецификации и ревью с SHA-256 и проверкой целостности.
- Обязательный quality gate на пути существующей кнопки Deploy: спецификация,
  синтаксис Python, наличие и запуск unittest в Docker без сети и секретов.
- Ограничения песочницы: timeout, CPU, RAM, PID, non-root, read-only, без capabilities.
- Развёртывание проверенного снимка, проверка HTTP/завершения скрипта,
  автоматическая попытка возврата предыдущего релиза при неготовности и ручной откат.
- Накопление уроков с привязкой к свидетельству релиза, утверждением владельцем,
  локальным сохранением и лексическим подбором утверждённого опыта в контекст агентов.
- Product Vision и PROJECT_RULES автоматически поступают в контекст основных ролей.
- Удалены опубликованные учётные данные из текущего кода и документации;
  production-конфигурация требует явных секретов.

Это основание, а не завершённая реализация vision. Тесты созданного продукта пока
пишет Coder: независимую генерацию приёмочных тестов должен выполнять Tester.

## Следующие этапы и критерии приёмки

1. **Надёжное управление SDLC.** Персистентная очередь, транзакционные переходы,
   checkpoint графа, возобновление после рестарта, идемпотентность и блокировки между
   процессами; тест с остановкой backend на каждом этапе. Сейчас задачи и HITL — в памяти.
2. **Независимая проверка продукта.** Tester получает критерии из утверждённой Spec,
   создаёт и запускает приёмочные и browser-тесты; Reviewer выдаёт структурированный
   блокирующий вердикт. Нужны отрицательные сценарии и контроль качества тестов.
3. **Воспроизводимая сборка.** Lockfile зависимостей продукта, сборка OCI-образа,
   digest вместо плавающего тега, SBOM и артефакты сборки; повторная сборка на чистом сервере.
4. **Реальные целевые платформы.** Сейчас поддержаны стандартная библиотека Python
   и статическая публикация HTML. Нужны адаптеры Node, Expo/native, установка
   зависимостей в стадии сборки, удалённая доставка по SSH с ограниченным ключом.
5. **Эксплуатация.** Внешняя readiness/liveness, метрики, журнал инцидентов,
   резервирование и восстановление данных, миграции БД, проверяемый rollback данных.
6. **Инженерное обучение.** Автоматическая подготовка кандидатов из инцидентов,
   оценка эффекта на контрольных задачах, версии практик, откат неудачного урока.
   Текущий подбор — лексический; хеш-векторы Qdrant не являются семантической памятью.
7. **Усиленная граница безопасности.** Отдельный исполнитель с ограниченным API
   вместо Docker socket в backend, политики egress и профили gVisor/VM. Docker
   разделяет ядро с хостом и не обеспечивает изоляцию уровня виртуальной машины.

## Совместимость

Существующие ADI, данные, промпты и запущенные контейнеры не мигрируются и не удаляются.
Новые проверки применяются при следующем Verify/Deploy. Старый некорректный исходник
теперь блокирует выпуск с диагностикой. Мобильный макет остаётся доступен как preview,
но не заменяет выпуск реального приложения. Откат кода не откатывает данные.
